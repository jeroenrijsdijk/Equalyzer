changelog = 1.12.0 Bay counts no longer come from plain rounding. A 17.86 m strip used to become four bays of 4.47 m; it now becomes three of 5.95 m, because a bay shorter than the minimum is worse than a roomy one. Both neighbouring counts are considered and the ones landing between the minimum and 1.5x the nominal size win. The minima are configurable, defaulting to 4.80 m along the car and 2.40 m across it, and the dialog reports when the bays end up away from nominal.
  1.11.0 The layer you split stays the active layer. Adding the Split Parts layer used to take the focus, which interrupted the draw, split, draw again rhythm.
  1.10.1 Fixed "cannot access local variable 'result_layer'" on the second and later split into an existing Split Parts layer: the reuse path skipped the block that assigned it.
  1.10.0 Bay mode can now replace the original. A new choice in the dialog: collect the bays in the Split Parts layer, do that and delete the original polygon, or replace the original in the source layer by its bays, which inherit its attributes. Source-layer edits go through one named edit command, so Ctrl+Z undoes a whole split; if the layer was already in edit mode the change joins that session instead of being committed. Primary key fields are left for the provider to fill.
  1.9.0 Areas are now measured in square metres for geographic layers as well, by forcing an ellipsoid; they used to come out as square degrees and rounded to 0.0000. Repeated splits of the same source layer now collect in one "Split Parts" layer instead of creating a new one each time. Every attribute of the source feature is copied onto its parts, with a src_ prefix only where a name would clash. part_id is numbered per source polygon instead of per run.
  1.8.0 Layers in a geographic CRS are now handled correctly. Angles and distances cannot be computed in degrees: at 52 degrees north a degree of longitude is 62% of a degree of latitude, so a perpendicular found in the coordinates lands up to 25 degrees off on the ground, which is what turned parking bays into rhombi. Strips are now measured and cut in the UTM zone of the data and the parts are transformed back to the layer CRS.
  1.7.2 Fixed areas reported as 0.0000: QgsDistanceArea was given its ellipsoid before its source CRS, which builds the transform against the wrong CRS. The strip axis is now computed from the polygon's own convex hull (minimum-width direction) instead of orientedMinimumBoundingBox, so bays are cut square across the strip even when the polygon is a skewed parallelogram. The measured size, fit and cut angle per strip are written to the log.
  1.7.1 Bay mode no longer needs a selection: start it with nothing selected and draw a line over the strip, which picks the polygon. The cut direction still comes from the strip's own axis. A non-metric CRS is no longer refused; strip sizes are measured on the ellipsoid instead, with a warning.
  1.7.0 New "Split into Parking Bays" action. Select the strips and press the button: each strip is measured with its own oriented bounding box, the short side decides whether bays lie head to tail (cut every 5 m) or side by side (cut every 2.5 m), and the number of bays follows from the length. No direction line and no part count to type, and a whole selection can be done in one go because every strip gets its own axis. Bay sizes are configurable and the dialog flags strips whose length is not a sensible multiple, whose depth matches neither size, or that are too curved for a rectangular axis.
  1.6.1 The direction line can now pick the polygon for you. Start Equalyzer without a selection, draw the line across the polygon you want, and the one the line runs through the most is selected in the layer. An existing selection is always respected, so splitting several polygons at once still works.
  1.6.0 Rebuilt "split into N equal parts". Cut positions now come from the exact cumulative-area profile of the polygon (closed-form solve) instead of a binary search, and the parts are produced by intersecting with band polygons instead of splitGeometry, so they always add up to the original. Ellipsoidal measurement is corrected with local Newton steps. All absolute area thresholds replaced by relative ones: the old ones silently discarded parts in projects that measure in square degrees. Ships test_equal_parts.py, runnable from the QGIS Python console.
  1.5.1 Diagnostic build: logs every step of the split pipeline to the Equalyzer tab of the Log Messages panel. Set DEBUG = False at the top of polygon_splitter.py to silence it.
  1.5.0 QGIS 4 (Qt6) compatibility while keeping QGIS 3 (Qt5) support. All Qt and QGIS enums now use their fully scoped, version-neutral spelling. Version-dependent details (QgsField type argument, snapping configuration, unit/geometry enum names, vector file writing, QAction import location) are isolated in one compatibility block at the top of polygon_splitter.py. Snapping setup can no longer break the direction tool. Added qgisMaximumVersion=4.99 so QGIS 4 will load the plugin.
  1.4.5 Added strict straight-cut splitting as the primary path for area and count modes, preserving original polygon boundaries except at real cut intersections. Falls back to the connected splitter when strict cuts cannot keep connected single-polygon parts, and now reports fallback use in Preview, Apply, and the QGIS message log. Updated splitGeometry calls for QGIS 3/4 compatibility.
  1.4.2 Added saved Precision setting for connected concave splitting. Higher precision uses finer strip graphs, multiple seed offsets and more rebalancing iterations; dialog geometry is saved/restored through QGIS settings.
  1.4.1 Removed unsupported QgsGeometry.boundary() call for older QGIS versions. Uses bbox-overlap plus geometry distance for strip adjacency. Evaluates multiple strip resolutions and keeps the best balanced exact-count result.
  1.4.0 Replaced count-mode concave splitting with connected graph partitioning. Produces exactly the requested number of connected output polygons. Added boundary-node rebalancing to improve equal-area results on irregular shapes.
